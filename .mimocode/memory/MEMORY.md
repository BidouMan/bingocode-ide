# Project memory
_Durable project-level knowledge. Persists across all sessions in this project. Edit only content under italic instructions._

## Project context
_BingoCodeIDE_ — Tauri v2 + Vue 3 + PixiJS desktop IDE for game development with a Python engine (`bingo_engine.py`). Refactored from a PySide6 version (see sibling project MyIDE for legacy knowledge). Two modes: game mode (visual editors + code + preview) and IDE mode (Python editing + run/stop). Engine runs in subprocess, communicates via JSON over stdout/stdin.

## Architecture decisions
_Major design choices with rationale._

- **PySide6 → Tauri v2 refactor**: Python engine retained as subprocess. JSON commands over stdout/stdin.
- **Two tab systems**: `gameTabs` (game mode) and `codeTabs` (IDE mode). Switching mode preserves both.
- **GameCanvas mounts only when running**: Prevents PixiJS mouse capture. Events scoped to canvas element, not window.
- **Game mode three sub-pages**: `activeEditorMode` controls `'code'`/`'sprite'`/`'map'` views. `setResourceTab()` is ONLY for sidebar switching (角色/场景/声音/代码).
- **Game mode navigation invariant**: All `setGameMode()` calls in game mode must pass `true`. Only `toggleGameMode()` (user-facing mode toggle) may set it to `false`. When navigating between editors within game mode, only `setActiveEditorMode()` should change — never touch `isGameMode`. [ses_f4cfba0c5ffe]
- **Code mode fully isolated**: Own menu, never modifies game-mode state.
- **Two execution modes**: Default Python (terminal output) + Game engine mode (PixiJS rendering). [ses_0f3269daffe]
- **Bundled Python**: python-build-standalone. `resolve_engine_env` fallback: bundled → venv → system. [ses_0f3269daffe]
- **移除代码检查按钮**: pyflakes 静态分析与运行时 Python 异常提示高度重叠，对目标用户（小学生）无实际价值，完全移除。pyflakes 也从 PluginManager 内置包列表移除。[ses_04894c7f7ffe]
- **本地图片统一用 invoke 读取**: 不使用 `convertFileSrc` + `fetch`。`convertFileSrc` 生成的 asset protocol URL 对中文路径编码有问题，`fetch` 对本地路径无效。统一用 `invoke('read_image_as_data_url')` 读取本地图片返回 data URL。适用于：缩略图加载、地图编辑器瓦片集加载、GameCanvas 运行时渲染。[ses_f4cfba0c5ffe]
- **世界边界钳制仅重力地图生效（2026-10-15, commit eb99fa3）**: `_resolve_collision` 的 world_bounds "隐形墙"钳制改为 `gravity=True` 才执行。理由：钳制会架空全部边界 API（edge_bounce/is_touch_edge/is_out_side/auto_destroy 子弹销毁）——无重力地图（俯视/太空）自由移动，边界语义交给用户代码；重力地图（平台）边界仍是墙。瓦片/图像碰撞两种模式都保留。[ses_ec075fac1ffe]
- **Vue store watch 三陷阱（2026-10-20 揘边 UI 迭代取证，跨任务耐久）**: ①**同 tick 值往返不触发**——`setSelection` 同步块内 count 1→0→1，watch 新旧值相同（都是 1）直接不触发 → 依赖"选中变化"的同步必须挂在必经函数（如 syncVectorSelBox）内联调用，不能靠 watch 计数器；②**同值写入不触发**——`store.x = true` 当已是 true 时 watch 不触发 → 勾选/开关类信号需配 tick 计数器（`xxxTick++`）做边沿强制，watch getter 写成数组 `[value, tick]`；③**多 watcher 同 flush 按注册序执行**，A watcher 内改 store 会把受影响 watcher 追加到本 flush 尾部 → 抑制窗口不能立即解锁，须 `nextTick(() => lock=false)`（nextTick 回调在 flush 之后）。[ses_ebce1d478ffe]

- **标注编辑功能（中心点/碰撞/挂点）落位 = 主精灵编辑器中央画布，标注图层体系（2026-10-20 讨论收敛）**: 三者本质是"依附于帧的几何标注数据"，放动画编辑器和绘制页都不合适——参照 Unity Sprite Editor 同画布多模式（Pivot/Custom Physics Shape 共享手柄+数值面板）。布局：画布顶部图层开关条（中心点/碰撞/挂点可多层同显，后两者灰态"即将"占位）+ 底部浮动属性条（X/Y 数值、作用域分段控件、预设、恢复统一）+ 十字拖动手柄（统一绿/覆盖蓝）。**作用域模型**：数据层 = sprite 级默认 + frames[i] 可选单帧覆盖（碰撞/挂点同构）；交互默认作用域"全部帧"，"仅当前帧"开关才写覆盖；覆盖帧造型列表打角标 + "恢复统一"清除；洋葱皮显示相邻帧标注（防碰撞框动画抖动）。动画预览区只读显示标注（验证用，不编辑）。落地顺序：先中心点（引擎已读 manifest.pivot），框架搭好后碰撞/挂点=加新图层零新学习成本。**原型已获用户认可（2026-10-20「目测 还不错 进入开发吧」），进入落码**：per-frame 覆盖存 manifest `frames[i].pivot`（saveBsfManifest 整体回写自动持久化）、引擎 `_setup_hitbox_bsf` 单点回退 `frame.get("pivot") or _bsf_pivot`、协议/GameCanvas 零改动（vox/voy 本就逐帧下发）、重打包按帧名 `carryFramePivots` 保覆盖。交互基准=`design-prototypes/sprite-annotation-editor.html`（自包含单文件、内嵌 boy.bsf 真实素材、QSS 配色）。**落地完成并提交 `4768bbc`（2026-10-20，master，用户实测验收"功能是可以用的"；vue-tsc/build/引擎冒烟全过）**。用户验收后 UI 校准定调：①标注类 UI **不加说明性文字**（操作提示/作用域提示/幽灵标签/tooltip 全删，只留功能标签）；②chip 图标化（中心点.svg）；③「标注图层」分组标题删除；④「重置」按钮=统一 pivot 回加载时快照+清全部覆盖；⑤顶部工具条与底部浮动条曾双份并存，**2026-10-21 用户定案：删掉画布底部悬浮条 `.anno-props`，顶部 `.anno-toolbar` 成为标注控件唯一入口**（浮层遮挡画布底部且控件与顶部完全重复，见「### 角色编辑器」末尾条目）。注意：commit 时仓库内置资源钩子自动暂存 engine/assets 全部变更（4768bbc 卷入用户自行重打包的 .bsf 库：中心点化+ganda/warrior/minicract 改名+删除数个大画布包）。[ses_ffe5ea5dbeec0ffeBn9Er0qjwZ]

- **渲染模式三态 + 「自动」按素材自然尺寸判定（2026-10-21 用户报"小图很糊"后定调）**: `RenderMode = 'auto' | 'smooth' | 'pixelated'`，**默认 auto**（`src/utils/renderMode.ts` 是唯一判定出口，`editorStore.renderMode` 从它引类型）。auto 口径：`Math.max(naturalW, naturalH) <= SMALL_ART_MAX_SIDE(128)` → `nearest`，否则 `linear`；尺寸未知保守走 linear。**为什么是尺寸而不是"当前渲染比例"**：linear 只在**缩小**时正确（放大只会抹开像素=糊）、nearest 只在**放大/1:1** 正确（缩小抽样丢细节+闪边）；编辑器各显示面（预览 248px、造型缩略图 36px、画布滚轮 zoom）对现有素材几乎都在放大 ⇒ 小图一律 nearest；而"渲染比例"虽是真根因变量，却随 zoom 与玩家 `size` 每帧变化（sampler 反复切换=抖动 + 用户明确担心"一个游戏很多角色"的运行期算力）。**GameCanvas 同走 auto 但不产生每帧成本**：`textureCache` 按 imagePath 去重（同角色多实例共享一张贴图）+ `sharedInFlightTextures` 合并并发 ⇒ 判定次数=图片文件数；判定体两次整数比较，结果进 `WeakMap<TextureSource>`，写 `source.scaleMode` 一次性（不重上传纹理）。**.bsf 的自然尺寸必须用 `raw_cw/raw_ch`（引擎 CREATE/UPDATE 已下发=帧内容尺寸），不能取 sheet.png**（拼图集会被误判为大插画）。作用域：角色编辑器 + 游戏画面；地图编辑器与资源面板缩略图暂不纳入（其 `renderMode === 'pixelated'` 三元式在 auto 下自然落 smooth = 与旧默认一致，无回归）。[ses_ffe5ea2dc151cffeO0vkc0iUh8]

- **WKWebView 三连坑：CSS `image-rendering` 不可靠 → 只能 canvas 自绘（2026-10-21 本会话连撞）**: ①**CSS `image-rendering: pixelated` 会被祖先 `transform: scale()` 的合成层平滑重采样覆盖**；②改成**布局尺寸**放大图片（`width/height = 自然尺寸 × zoom`）后用户实测**仍糊**（"目前还是模糊，比如 minicract_1"）⇒ ③最终只能 **canvas 自绘 + `ctx.imageSmoothingEnabled = false`**（浏览器无法干预 canvas 采样）。④**改完渲染/缩略图管线后用户"看不到变化"，先查会话内缓存**：`spriteLibStore.items[].thumbUrl`（`loaded=true` 不再重算）与 `MainLayout.spriteThumbnails` 都是懒加载一次性写入，**Vite HMR 只换模块不清 Pinia state** ⇒ 必须重启 dev / Cmd+R 才能验；同理凡"只在加载时算一次"的派生数据都要先排除缓存因素再改代码。[ses_ffe5ea2dc151cffeO0vkc0iUh8]
- **canvas 侧任何"放大"都必须显式关掉 `imageSmoothingEnabled`（2026-10-21 缩略图模糊真凶）**: `ctx.drawImage` 默认双线性插值，把 13×28 的像素画放大到 137px 会把**糊烤进像素**——之后无论 CSS 怎么设 `image-rendering` 都救不回来（画布缩略图上线两轮后、用户第三次报"模糊"才定位到）。规则：**缩放前按素材大小决定 `imageSmoothingEnabled`**（内容最长边 ≤128 → false / 大插画 → true）。canvas 自绘还要自理：①backing 尺寸（nearest 按 `devicePixelRatio`；smooth 只到自然尺寸以省内存；单边 ≤4096）②刷新时机（帧/zoom/模式 change，Vue 用 `watch(..., { flush: 'post' })` 保证 canvas 已挂载）③解码缓存 `Map<url, HTMLImageElement>`（换角色清空）④并发 draw token 防乱序。[ses_ffe5ea2dc151cffeO0vkc0iUh8]
- **"素材糊不糊"先用 Pillow 验尸再改渲染代码（2026-10-21，省两轮弯路）**: 复刻前端 `cropSheetFrame`（把 sheet 的帧 rect 按 offset 画回 canvas 尺寸画布）→ 统计 alpha 直方图 + rect/offset 整数性。`minicract_1.bsf` 实测 canvas 54×42 / 48 帧 / 帧 rect 13×28 / offset 全整数 / **alpha 仅 0 与 255 两种值** ⇒ 干净像素画，问题必然在显示端。另可一并测内容占画布比（`getbbox()`）。[ses_ffe5ea2dc151cffeO0vkc0iUh8]
- **固定画布烘焙后 `naturalWidth` 失去"素材大小"语义 + per-thumb 渲染判定应删除（2026-10-21）**: 缩略图统一 160×160 后 `naturalWidth` 恒 160，不能再当素材尺寸喂自动判定；更关键的是**没必要判**——160px 画布在 50~144px 格子里**永远被缩小**，CSS 平滑才是正确采样（pixelated 缩小 = 抽样 aliasing）。故 `MainLayout.spriteThumbSizes`/`setSpriteThumb`/`spriteThumbRendering`、`SpriteLibPage.thumbRendering`、`SpriteLibItem.thumbW/thumbH` 全部删除。[ses_ffe5ea2dc151cffeO0vkc0iUh8]
- **用户报"没变化/没效果"的排查顺序（2026-10-21 三次踩坑后固化）**: ①**会话内一次性派生数据**（Pinia 缩略图缓存；Vite HMR 不清 store ⇒ 必须重启 dev）②**设置项**（`editorStore.renderMode` 是否被手动设成 `Smooth`，那时平滑是设计行为）③**用户说的是哪个面**（编辑器画布 / ANIMATION 预览 / 库页缩略图 / 资源面板缩略图——多次反馈都只说"模糊"）④才查代码。[ses_ffe5ea2dc151cffeO0vkc0iUh8]

- **`max-width/max-height` 会夹死显式 width/height（2026-10-21 预览 ×2 失灵）**: 预览图从"wrap `transform: scale(previewScale)`"改成"显式 `width/height = min(自然,248) × scale`"后，CSS 里遗留的 `max-width/max-height: 248px` 会把 496px 夹回 248px ⇒ 缩放档位失效。改法：删 `max-*`。（预览现已改为 canvas 自绘，尺寸由 `drawImageCrisp` 写 `style.width/height`，CSS 只剩 `display:block`。）[ses_ffe5ea2dc151cffeO0vkc0iUh8]
