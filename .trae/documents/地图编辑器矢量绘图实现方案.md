# 地图编辑器矢量绘图实现方案

## Context

地图编辑器目前只支持位图绘制：画笔/橡皮/形状直接改选中图片图层的像素，工具栏“矢量”按钮处于禁用状态。角色绘制页已经有一套完整的 Paper.js 矢量引擎（`usePaperScope.ts` + `PaintArtboard.vue`），支持选择/塑形/画笔/橡皮/填充/文字/直线/矩形/椭圆/取色、复制粘贴、翻转、组合、层级与撤销重做。

目标：在地图编辑器中复用同一套矢量引擎和交互，让选中的图片图层可以在“矢量模式”下像角色绘制页一样绘制，退出矢量模式时把矢量内容烘焙进图片像素，地图存档仍保持 PNG `imagelayer` 格式不变。

关键约束：
- 图片图层可能带 `position / rotation / scaleX / scaleY`，地图视口还有自己的缩放平移，坐标必须完整映射。
- 不破坏角色绘制页现有行为；`usePaperScope` 的改造必须全部为可选参数。
- 全局 `paintStore` 共享，需在地图页内可控地切换 `mode / activeTool / artboardWidth/Height`，退出时恢复。

## 推荐架构

**给 `usePaperScope` 增加可选视口适配器，地图侧新建独立矢量画布覆盖层；单帧、无位图代理。**

- 矢量画布铺满地图画布 stage（`position:absolute; inset:0`），不做 CSS transform；缩放/平移/旋转全部写入 `paper.view.matrix`。
- 新增 `PaperViewport` 适配器：`clientToArtboard`、`getViewMatrix`、`getClipPath`、`getArtboard`。地图实现把“图片像素坐标 → 图片本地归一化 → 世界 → 屏幕”合成一个仿射矩阵，因此旋转、非等比缩放都天然正确。
- 单帧模式：跳过 `store.frames / activeFrameIndex` 相关逻辑，矢量内容只属于当前图片图层。
- 第一阶段不启用 Paper 位图代理：Pixi 精灵继续显示底图，避免双影；矢量对象画在透明覆盖层上。退出矢量模式时把 `project.draw` 栅格合成进 `paintSession.canvas`。
- 矢量选中框/塑形锚点/文字编辑框：在覆盖层内使用与图片像素坐标一致的 SVG/textarea 容器（整体套用同一仿射矩阵），复用 `store.vectorSelBox / reshapePts / textEdit` 的投影数据。

## 关键文件

### 修改

- `src/components/paint-editor/composables/usePaperScope.ts`
  - 新增可选第 4 参数：`viewport?: PaperViewport`、`singleFrame?: boolean`、`proxy?: boolean`、`onRefreshRequest?`。
  - `clientToArtboard`：优先委托 `viewport.clientToArtboard`。
  - `syncVectorView`：优先用 `viewport.getViewMatrix/getClipPath`；否则走现有角色页算法。
  - `singleFrame` 时跳过 `watch(store.activeFrameIndex)`、帧导入导出；`proxy=false` 时 `syncBitmapRaster` 直接返回。
  - 导出 `refreshView()` 供地图侧在视口/图片变换变化时调用。

  - 新增 `enterVectorLayer() / commitVectorToPixels()`：进入时设置 `paintStore.artboardWidth/Height = 图片绘制画布尺寸`，退出时 `commit`。
  - 暴露 `vectorUndo/redo/copy/paste/delete/flip/...`、`refreshVectorView()`、`vectorViewMatrixCss`，以及平移/缩放转发方法给覆盖层。

  - 转发模式切换与新增的矢量操作事件。

  - `imageTool` 联合类型扩展：`reshape/text/eyedropper`。

## 数据流与生命周期

```
pointer(覆盖层) → viewport.clientToArtboard(图片像素坐标) → paper 对象
paper view.matrix = 图片像素 → 屏幕（含图片旋转/缩放 + 地图缩放平移）
退出矢量模式 → beforeExport() → getFrameRaster(0) → drawImage 到 paintSession.canvas
            → 压一步位图撤销 → flushPaintSave() → 更新 imagePath
```

进入/退出：
1. 仅当 `activeMode==='image'` 且已选中图片图层时允许切矢量。
2. 进入：记录 `paintStore` 的 `mode/artboard/zoom/pan` 快照；设置 `mode='vector'`、artboard=图片像素尺寸；创建/复位 paper project。
3. 退出（切位图、切图层、切地图、卸载、保存地图前）：统一 `commitVectorToPixels()` 烘焙 + 清理矢量选中/历史，再恢复 `paintStore.mode='bitmap'` 与 artboard 快照。
4. 撤销衔接：矢量阶段使用 Paper JSON 快照栈；烘焙前压一步位图像素快照，保证烘焙结果可位图撤销。

## 实施顺序

### 阶段 A：可用闭环
1. `usePaperScope` 增加可选适配器/单帧/无代理参数，角色页不传时行为不变。
2. 实现地图 viewport 适配器（矩阵、裁剪、坐标换算）。
3. MapCanvas 挂载矢量覆盖层与 paper 引擎，打通画笔/橡皮/填充/直线/矩形/椭圆/取色、选择移动、撤销重做。
4. 模式切换 UI、右侧面板、浮动工具条路由。
5. 所有退出路径统一烘焙并保存 PNG。

### 阶段 B：完整对齐角色页
6. 文字工具（textarea overlay 复用 `store.textEdit`，容器套用同一仿射矩阵）。
7. 塑形工具（锚点/曲线折线/方向键微移/删除锚点）。
8. 复制/剪切/粘贴、翻转、删除、组合/解组、层级上移下移。
9. 快捷键路由（Esc/Delete/方向键/Ctrl+C/X/V）与矢量模式下禁用位图浮动选区逻辑。
10. 光标与裁剪细节打磨、边界情况处理。

## 风险与规避

- **全局 paintStore 污染**：进入/退出严格快照与恢复；角色页 `reset()` 仍是 mode 唯一复位点。
- **坐标错位**：以 Pixi 精灵实际屏幕四角做对齐自测；覆盖层 canvas 不做 CSS transform；裁剪使用图片四角 polygon。
- **双影/重影**：阶段 A 不启用代理，Pixi 精灵保持显示。
- **丢内容**：切图层/切地图/卸载/保存地图四条路径全部调用烘焙；`watch(selectedImageLayerId)` 兜底。
- **角色页回归**：所有引擎改动均为可选参数；先跑角色页手测再跑地图页。

## 验证

- `npx vue-tsc --noEmit`（关注 map-editor / paint-editor / stores）
- `pnpm build`
- 手测：
  1. 未旋转/等比图片：四档地图缩放下画笔落点与光标一致。
  2. 旋转 30°、非等比缩放的图片：绘制落点仍准确，裁剪不越出图片。
  3. 矢量绘制后切位图、切图层、切地图、关闭再打开，PNG 保留内容。
  4. 矢量撤销/重做与烘焙后的位图撤销各回一步。
  5. 角色绘制页矢量工具、缩略图、保存流程保持原样。
